# Шпаргалка Sputnik

Краткий справочник по синтаксису и повседневным приёмам. Основан на [спецификации языка](../sputnik_unified_final_spec.md) в рабочем дереве, прежде всего на частях I–III; [грамматика рантайма](../sputnik_runtime_project_design.md) уточняет параметры блоков и лексические правила. Примеры независимы: имена `users`, `cfg` и `load` обозначают данные и API приложения. Необязательные профили и дополнительные формы из эталонной реализации отмечены отдельно.

## 1. Основы

```sputnik
# Отступы задают тела конструкций; двоеточие открывает непустое тело.
def double(x): x * 2                 # неявный возврат: последнее выражение
def no_op()                         # пустое тело: двоеточие не нужно
n = 1_000; n += 1
hex = 0xFF; bits = 0b1010; mode = 0o755
ratio = 1.25e-3
name = "Ada"
text = "Hello, #{name}! #{2 ** 10}"  # интерполяция; экранирование: \n \t \u{1F600}
literal = "\#{name}"                # буквальный маркер интерполяции
state = :ready                      # Symbol
```

Ложными считаются только `false` и `null`: `0`, `""`, `[]` и `{}` истинны. Имена могут оканчиваться на `?` (предикат) или `!` (обычно мутация или потенциально опасная операция); эти суффиксы — часть имени. Перед `#` в комментарии в конце строки нужен пробельный символ.

| Задача | Синтаксис / правило |
| --- | --- |
| Арифметика | `+ - * / // % **`; `//` округляет вниз; `**` правоассоциативен: `2 ** 3 ** 2 == 512`; `-2 ** 2 == -4` |
| Сравнение / сопоставление | `== != < <= > >=`; `T === value` проверяет тип или сопоставитель |
| Битовые операции | `& \| ^ << >>`; `^` — XOR, а не возведение в степень |
| Логика | `not`, `and`, `or` — в порядке убывания приоритета; `and`/`or` используют короткое замыкание и возвращают операнды |
| Принадлежность | `x in xs`; `key in map`; `"sub" in text` → вызов `contains?` у правого операнда |
| Метод принадлежности | `x.in?(container)` → `container.contains?(x)`; ровно один контейнер, результат `Bool` |
| Альтернативные значения | `x.one_of?(a, b)` / `x.one_of?(*targets)` → `==` получателя до первого совпадения; без аргументов → `false` |
| Значение по умолчанию только для null | `value ?? fallback` сохраняет `false` и `0`; форма задана спецификацией, но см. примечание о текущем бинарнике ниже |
| Значение по умолчанию для ложного значения | `value or fallback` |
| Присвоить значение при null | `value ?= fallback`; сохраняет `false`, `0`, пустые строки и коллекции |
| Присвоить значение при ложном значении | `value or= fallback`; заменяет `false` и `null` |
| Явное отсутствие | `text.trimmed.presence() or "anonymous"`; `xs.nonempty() or defaults`; `n.nonzero() or 100` |
| Последний результат | `$_` доступен только для чтения и принадлежит текущей функции или блоку; выражения-инструкции, **включая присваивания и вывод**, обновляют его |

Многострочные string-tag макросы поддерживают повторение участка шаблона:

```sputnik
from system import cmd
command = cmd"""
  echo
  %for value with_index i in values:
    --item=#{value}
  """
```

`%for` использует обычные паттерны, аргументы Map и `with_index`; коллекция
вычисляется один раз. Dedent закрывает тело, дополнительный отступ удаляется,
строка директивы не выводит перевод строки. `%#` — комментарий шаблона, `%%`
выводит `%`. В строках без tag директивы остаются текстом. Провайдер сохраняет
семантику интерполяции: HTML-экранирование, SQL-параметры или непрозрачные аргументы
команды. Реализован только `%for`, без `%if`.
[Контракт провайдера](engineering/string-template-loops-v1.md).

Внешнее тело задаётся аннотацией `template("./page.html.sv")` непосредственно
перед `def page(title as Str, subtitle: "")` без тела. В шаблоне видны параметры
и импорты объявления. В build manifest регистрируется `source_formats` с полями
`suffix`, `module`, `macro`. Вызов функции обычный; файл `.sv` сохраняет отступы
и не требует кавычек-разделителей. [Контракт](engineering/external-templates-v1.md).

## 2. Коллекции, диапазоны и отсутствие значений

```sputnik
xs = [1, 2, 3]                      # Array
pair = (1, "a"); single = (1,)      # Tuple: запятая имеет значение
tags = {:read, :write}; empty = Set{}
user = {name:, active: true}         # {name:} означает {name: name}
opts = {mode::fast}                 # mode: :fast
lookup = {(user_id): user}          # вычисляемый ключ Map: скобки обязательны
strict = StrictMap{name: 1, "name": 2}

ys = [0, *xs, 4 if enabled?]        # условный элемент пропускается при false
opts = {**defaults, debug: true if debug?}
tags = {:read, *extra if enabled?}

xs[-1]                             # последний элемент; неверный индекс → IndexError
xs[?99]                            # необязательный индекс → null при отсутствии
user[:name]                        # строгий поиск; нет ключа → KeyError
user[?:email]                      # необязательный ключ → null при отсутствии
user[:email] ?= "unknown"          # вставить ключ или заменить null
xs[0] ?= 10                        # заменить только null-элемент
xs[1] or= 20                       # заменить false или null
maybe_user.?.[?:email]              # допускает и null-получатель, и отсутствие ключа

(1..5:2).array                     # [1, 3, 5]; правая граница включена
(1...5:2).array                    # [1, 3]; правая граница исключена
(5..1:-1).array                    # убывание: нужен отрицательный шаг
xs[1...3]; xs[0..:2]; xs[-1..:-1]   # срез / каждый второй / обратная копия
Array.of(3): []                    # три разных изменяемых массива
Array.of(5) |i|: i * i             # [0, 1, 4, 9, 16]; псевдоним: Array.build
Array.filled(3, 0)                 # повтор значения; для объекта — одна общая ссылка
5.times.map: $it * 2               # [0, 2, 4, 6, 8]
```

`{}` — пустой Map, `{x}` — Set с одним элементом. Обычный Map считает `:name` и `"name"` одним ключом и выдаёт именные ключи как строки. `StrictMap` различает их. Повторный ключ Map перезаписывает значение; Set удаляет дубликаты. `Map{…}` и `Set{…}` — явные конструкторы; существуют также формы `HashMap{…}`, `StrictHashMap{…}` и `HashSet{…}`, но текущий эталонный профиль не гарантирует производительность хеш-таблицы.

`[?key]` обрабатывает отсутствие, а не произвольные ошибки, и доступен только для чтения. Используйте `contains?(key)` / `has_index?(i)`, чтобы отличить отсутствующий элемент от сохранённого `null`. `.?.` защищает только от null-получателя: каждый nullable-шаг нужно защищать отдельно. Открытые диапазоны (`1..`, `1..:2`) требуют конечной границы перед материализацией или раскрытием; срез задаёт её сам. Нулевой шаг недопустим.

`?=` и `or=` вычисляют цель один раз, а правую часть — только при необходимости записи; возвращают сохранённое или присвоенное значение. Индексная цель использует мягкое чтение и обычную запись: отсутствующий ключ Map вставляется, а запись за границы Array даёт `IndexError`. `a?=b` означает `a ?= b`; для присваивания имени с суффиксом нужен пробел: `ready? = false`.

`in?` и `one_of?` доступны на любом значении, включая `null`, `false`, коллекции
и объекты типов. `2.in?([1, 2])` истинно; `2.one_of?([1, 2])` ложно: коллекция
без `*` — один целый аргумент. `[1, 2].one_of?(*[[1, 2]])` истинно.
`one_of?` проверяет равенство, без matcher-семантики: `5.one_of?(Int, 1..10)`
ложно. Оба метода запрещают keywords/блоки и требуют `Bool` от протоколов;
неподдерживаемый контейнер у `in?` даёт `TypeError`. Выражения аргументов вычисляются
до сравнений; короткое замыкание относится к самим сравнениям. Пользовательский
метод имеет обычный приоритет перед стандартной реализацией.

## 3. Блоки и цепочки: пробелы имеют значение

```sputnik
users.map |u|: u.email.trimmed
users.map: $it.email.trimmed         # $it == $it1 == _1; $it2 == _2 и т. д.
numbers.map: $it * 2 .select: $it > 0 .reduce(0): $it1 + $it2
pairs.map |(key, value)|: "#{key}=#{value}"  # деструктуризация параметра блока

result = numbers
  .select: $it > 0
  .map if scale? |n|: n * 10
  .uniq()
```

**Без пробела перед точкой** вызов остаётся внутри однострочного блока; **пробел и точка** продолжают внешнюю цепочку. Блок прикрепляется к ближайшему вызову слева. Нумерованные аргументы существуют только внутри блоков без `|…|`, должны использовать последовательные позиции и всегда принадлежат ближайшему блоку. `map($it * 2)` — не синтаксис блока.

Bare вызов также принимает `name: expression` или многострочный `name:` с
отступом, включая expression position (`result = name: value`). В однострочной
форме двоеточие примыкает к имени; `name :symbol` её не открывает. Тело-Map
`json: {ok: true}` использует тот же общий синтаксис.

Аргументы bare call не переносятся на следующую строку. Для многострочного
списка откройте `method(` на строке вызова. Выражение `(a, b)` после завершённого
блока — отдельный tuple, в том числе для неявного возврата.

Условные сегменты цепочки записываются как `.call(args) if condition` или `.call if condition |x|: body` (также `unless`). Пропущенный сегмент передаёт получатель дальше без изменений и не вычисляет аргументы и блок. Его условие не распространяется на последующие сегменты. Соседние вызовы `.a().b()` принадлежат одному сегменту; пробел перед следующей точкой начинает новый.

## 4. Функции, типы и вызываемые значения

```sputnik
def greet(name as Str, prefix: "Hi") -> Str:
  "#{prefix}, #{name}"
greet("Ada", prefix: "Hello")
greet(*["Ada"], **{"prefix": "Hello"})

def apply(value, &block): block(value)
def relay(xs, &block): xs.map(&block) # передача через канал блока
def notify(value, &block): block.?.(value)  # отсутствующий блок — null

f = &Math.answer                    # ссылка: целевой метод не вызывается
f()                                # вызов вызываемого значения
method = &User#full_name            # несвязанный метод экземпляра
method(user)                       # получатель — первый аргумент
factory = User; factory("Ada")      # вызов класса == User.new("Ada")

obj.member                         # чтение свойства ИЛИ неявный вызов метода без аргументов
obj.member()                       # явный вызов метода; свойства не допускают эту форму
obj.member.()                      # прочитать член, затем вызвать полученное значение
callback.?.(42)                    # вызвать, только если callback не null

"42".int                           # свойство преобразования; также Int("42") / .to_int()
value.cast(Int)                    # явный протокол преобразования
value as Int                       # проверка существующего типа, БЕЗ преобразования
```

Параметры: `x`, `x = default`, `key:`, `key: default`, `x as T`, `key as T: default`; `@x` / `@@x` дополнительно сохраняют связанный аргумент в поле экземпляра или класса. Значения по умолчанию вычисляются **при каждом вызове**. В `def init(@x, @y = x)` локальное `x` обозначает новый аргумент; `@x` в значении по умолчанию читает старое состояние.

Типы: `T?` = `T | Null`; объединения `Int | Str`; кортежи `(Int, Str)`; обобщённые типы `Array[Int]`, `Map[Str, Int]`; записи `{id: Int, **Str}` (дополнительные значения должны быть строками). Аннотации необязательны; полного статического вывода типов это не обещает. Свойства преобразования: `.str .int .float .bool .symbol .array .tuple .set .map`; не добавляйте `()` к этим псевдонимам.

`*args` раскрывает конечные Array/Tuple/Range; `**opts` принимает Map или **доступное для чтения свойство `kwargs`**, возвращающее подходящий Map или представление. Ключи именованных аргументов должны быть допустимыми именами параметров; повторный аргумент — ошибка. Позиционные аргументы предшествуют именованным. Передаваемый `&block` должен стоять последним и использовать локальное имя; сначала сохраните `&Namespace.fn` в локальную переменную. `&obj.method` не поддерживается — используйте обёртку-замыкание.

## 5. Классы, свойства и композиция

```sputnik
mixin Named:
  def label(): self.name

class User:
  include Named                     # методы экземпляров
  def init(@name, @email: null)
  attr var name                     # чтение и запись @name
  attr email                        # только чтение @email
  attr set password from @secret    # только запись, собственное поле хранения
  prop greeting: "Hello, #{@name}"  # вычисляемый getter
  prop normalized_name:
    get: @name.trimmed
    set(value): @name = value.trimmed
  class_prop kind: :user
  class_method def build(name): User(name)

class Admin < User                  # наследование; пустой класс без двоеточия
u = User("Ada", email: "ada@example.org")
u.name = "Grace"                    # setter свойства
```

`@field` — поле хранения, а не публичный доступ; выставляйте его через `attr`/`prop`. `class_prop` и `@@field` относятся к классу. Ветки свойства не должны приостанавливать задачу. В методах объекта приоритет имеют лексические имена; неразрешённое имя ищется как `self.name`.

Повторный `class User:` / `mixin Named:` открывает существующее определение. `include A, B` примешивает методы к экземплярам; `extend FactoryMixin` внутри класса — к объекту класса. Сначала выбираются локальные методы, затем более поздние примеси, затем суперкласс. Инструменты работы с методами в рантайме: `define_method(User, :greet) |name|: …`, `send(user, :greet, "Ada")` и `def method_missing(selector, …): …` (сигнатура зависит от обрабатываемых вызовов). Изменения классов и таблиц методов требуют открытого мира диспетчеризации. Собственная индексация: `def [](key): …` и `def []=(key, value): …`.

В методе, определённом в классе, `super(args...)` вызывает одноимённый метод начиная с лексического суперкласса, сохраняя исходный receiver. `super()` передаёт пустой список аргументов; `super(value, option: option, &block)` явно передаёт параметры и блок. Поддерживаются конструкторы, `class_method` и вложенные замыкания. См. [вызовы суперкласса](engineering/super-dispatch.md).

## 6. Сопоставление с образцом и функции с несколькими ветками

```sputnik
[head, *tail] = xs                  # несовпадение → MatchError
{id: user_id, **rest} = payload

label = case! payload:
  when {id: n, name:} if Int === n and n > 0: "#{n}: #{name}"
  when null: "missing"
  else: "other"

def format(x, mode::short):
  when {mode::short}: x.str         # образец Map сопоставляет аргументы по именам
  else: "Value: #{x}"

def fact(0): 1                     # соседние простые def образуют ветки
def fact(n) if n > 0: n * fact(n - 1)
```

| Образец | Значение |
| --- | --- |
| `_`, `name`, `42`, `:ok`, `null` | Игнорировать / связать имя / сопоставить литерал |
| `^expected` | Сравнить с существующей привязкой |
| `(a, b)`, `[head, *tail]` | Деструктуризация последовательности; ядро спецификации ставит остаток последним |
| `{id:}`, `{id: n}`, `{id:, **rest}` | Связать именованный ключ / переименовать / захватить остальные ключи |
| `{id:, **_}`, `{id:, **null}` | Игнорировать лишнее / запретить лишнее; по умолчанию лишние ключи разрешены |
| `Int`, `Point(x, y)`, `Point(x:, y:)` | Проверка типа или константы; типизированная позиционная / именованная деструктуризация |
| `whole as [a, b]`, `n as Int` | Связать целое значение, затем сопоставить образец справа |
| `(0, x) \| (x, 0)` | Альтернативы должны связывать одинаковые имена; OR-образцы внутри блока оборачивайте в `\|…\|` |
| `in choices`, `n as in choices`, `{status: in [409, 410]}` | Принадлежность через `in?`; RHS — выражение без новых привязок; доступно во всех контекстах образцов |
| `when 1..10:` | Выражение-сопоставитель (`===`); только в `case` / `case!` |
| `pattern(matcher) with {id:, **null}` | Динамический сопоставитель с явными привязками; только в case или функциях с ветками |

Выбирается первая совпавшая ветка с истинным guard-условием. `case` без совпадения возвращает `null`; `case!` и функция с ветками поднимают `MatchError`. Пользовательские объекты участвуют через `===`, `deconstruct()` и `deconstruct_keys(keys)`; динамические сопоставители — через `match(value)`. Для сложных сигнатур используйте один `def` с ветками `when`; образец Tuple сопоставляет позиционные аргументы, Map — имена аргументов.

`in choices` вычисляет текущий контейнер один раз при достижении проверки, в том
числе внутри структур, параметров блоков и присваивания. Пропущенная ветка его
не вычисляет. Имена RHS читаются из внешнего окружения; читать имена, вводимые
тем же образцом, запрещено. Для оператора `|` внутри выражения нужны скобки:
`in (left | right)`. `Int | Str` сопоставляет типы, `in [Int, Str]` — объекты типов.

## 7. Условия и управление потоком

```sputnik
label = if ready? then "ready" else "waiting"
print "ready" if ready?             # модификатор инструкции; также unless
unless ready?: print "waiting"

value = if ready?:
  compute()
else if cached?:                    # псевдонимы: elif, elsif
  cached_value
else:
  null

while work?: step()
until done?: step()
do:
  step()
while work?
found = loop:
  if ready?: break :ok

for x in (0..15:2):
  if x == 6: break
  print x

for x with_index i in (1...100500:42):
  print x, i
  if i == 2: break

first_big = catch(:found):
  xs.each |x|:
    if x > 100: throw :found, x
  null
```

`if`, `case` и циклы — выражения. Цикл возвращает значение из `break value`, иначе `null`. `for` понижается в `for_each`; оба, как и `times` с блоком, всегда возвращают `null`. Голый `break` завершает такой обход; `break value` здесь запрещён. В `each`/`map`/`select` выход через `break` по-прежнему запрещён. Для обычного досрочного выхода используйте `find`/`any?`/ограничение ленивой последовательности; `catch`/`throw` пересекает вложенные вызовы и блоки. `next value` завершает только текущий вызов блока. `return value` в переданном при вызове блоке выходит из **метода или лямбды, создавших блок**; отдельная лямбда возвращает локально. `return` и `next` без аргумента используют `$_`, а не обязательно `null`.

`then` выполняет действия слева направо в той же области видимости, обновляя
`$_` после каждого: `load() then normalize($_)`. Приоритет ниже присваивания;
`x = first() then y = second()` — два присваивания. Постфиксный `if`/`unless`
охватывает всю последовательность: `rollback() then break if invalid?`.

В обычном переданном при вызове блоке `break value` завершает принимающий
вызов и становится его результатом; голый `break` возвращает `null`.
Проброс `&blk` сохраняет исходную цель. Все `ensure` выполняются; `rescue`
не перехватывает выход. Истёкшая цель или другая task дают `LocalJumpError`.

Смешивание inline `if … then … else …` с последовательностью требует скобок
(иначе `ParenthesesError`). Даже со скобками предпочтителен многострочный код:
`sputnik lint file.s` предупреждает о смешанных условиях (`L1001`), вложенных
последовательностях и трёх и более действиях на строке (`L1002`).
`obj.then()` остаётся вызовом метода.

`r"\d+"` и `r'\d+'` создают Unicode-regexp. Флаги примыкают к литералу: `r"^[a-z]+$"mi` (`i`, `m`, `s`, `x`, `U`); inline `(?mi)` также работает. `text ~= pattern` и `pattern ~= text` — одинаковый предикат поиска; отрицание через `not`. Захваты получаются через `pattern.match(text)`. В `r"#{text}"` Str-вставки экранируются как данные. Целое условие записывает итог в `$_`; `and`/`or` не публикуют промежуточные операнды.

## 8. Повседневные приёмы для коллекций

| Задача | Идиома |
| --- | --- |
| Очистить и удалить дубликаты | `users.map: $it.email.trimmed.downcased .uniq()` |
| Отфильтровать, затем преобразовать | `xs.select: $it > 0 .map: $it * 2` |
| Преобразовать и отбросить ложные результаты | `xs.filter_map: lookup($it)` удаляет `false`/`null`, сохраняет `0`/`""` |
| Преобразовать и развернуть результаты | `groups.flat_map: $it.members` |
| Агрегировать | `xs.reduce(0): $it1 + $it2`; `xs.sum`; `xs.product` |
| Обход ради эффектов | `for x in xs: …`; `xs.for_each \|x\|: …`; `for x with_index i in xs: …` |
| Значение / индекс / оба | `xs.find \|x\|: …`; `xs.find_index \|x\|: …`; `xs.find_with_index \|x\|: …` → `(x, i)` |
| Индекс в предикате | `xs.find.with_index \|x, i\|: …` → `x`; `xs.find_with_index.with_index \|x, i\|: …` → `(x, i)` |
| Найти / проверить условие | `xs.find: $it > 10`; `xs.any?: $it > 10`; также `all?`, `none?` |
| Сгруппировать / разделить | `users.group: $it.role`; `xs.partition: $it > 0` |
| Подсчитать по значениям / ключам | `xs.counts`; `users.counts: $it.role` → Map с количествами; `tally` — псевдоним с тем же необязательным блоком |
| Отсортировать / удалить дубликаты по ключу | `xs.sort: $it1 - $it2`; `users.uniq: $it.id` |
| Индексы / окна / пары | `xs.each_with_index \|x, i\|: …`; `xs.each(3, step: 1) \|window\|: …`; `xs.each_pair \|(a, b)\|: …` |
| Ограничить ленивое вычисление | `(1..).lazy.select: $it.even? .first(5)` |
| Объединить попарно / убрать null / развернуть | `xs.zip(ys)` ограничивается кратчайшим; `xs.compact` убирает null; `xs.flattened` разворачивает вложенные массивы |
| Операции над множествами | `a.union(b)`, `.intersection(b)`, `.difference(b)`, `.symmetric_difference(b)`; псевдонимы `\| & - ^` |
| Сформировать текст | `xs.join(", ")`; `text.lines`; `text.replaced("old", "new")` |
| Преобразовать Map | `m.map \|k, v\|: …` → Array; `m.transformed \|k, v\|: (k, v * 2)` → Map |
| Преобразовать ключи / значения | `m.transformed_keys \|k, v\|: k.str + "_copy"`; `m.transformed_values \|v, k\|: v * 2` |
| Преобразовать Map на месте | `m.transform! \|k, v\|: (k.str + "_new", v * 2)` → receiver; `transform_keys!` / `transform_values!` меняют одну сторону |
| Сохранить ключи Map | `m.select \|k, v\|: v > 0`; `m.transformed_values \|v\|: v * 2` |
| Объединить с обработкой конфликтов | `left.merge(right) \|key, old, new\|: old + new` |
| Необязательный вложенный поиск | `cfg.dig(:server, :port) ?? 8080` |
| Запомнить результат, включая false/null | `cache.get_or_set!(key): expensive(key)` — блок выполняется только для отсутствующих ключей |
| Скопировать | `xs.copy` — поверхностная копия; `xs.deep_copy` сохраняет циклы и структуру общих ссылок |

Коллекции вычисляются сразу, пока вы не сделаете их ленивыми. Для `reduce` на потенциально пустом входе лучше задать начальное значение. `each` возвращает получатель; `for_each`, `for` и `n.times: …` возвращают `null`. Все формы поиска возвращают `null` без совпадения. `.with_index` добавляет индекс с нуля к аргументам блока, сохраняя результат метода. `for` использует правила аргументов и паттернов `each`, включая `for k, v in map:`; диапазоны сохраняют `..`/`...`/`:step`. Блоки Map обычно получают **ключ и значение**; `transformed_values` получает **значение и необязательный ключ**. Методы мутации: `push!`, `filter_map!` (Array/Set), `compact!`, `flatten!`; неизменяющие строковые формы: `trimmed`, `upcased`, `downcased`, `reversed`.

## 9. Ошибки, очистка и явные результаты

```sputnik
class InputError < Exception:
  def init(@message)
  attr message

def parse_count(text):
  Int(text)
rescue TypeError, ValueError |e|:
  0
ensure:
  record_attempt()                  # при успехе, ошибке, return и раскрутке стека

value = try:
  risky()
rescue |e|:                         # перехват всех обычных поднятых значений
  fallback(e)
ensure:
  release()

raise InputError("bad input")
Ok(42).map: $it * 2                 # Ok(84)
Err("missing").or(0)               # 0
Err("missing").or_else |e|: recover(e)
Err(InputError("bad")).or_raise    # переход к raise/rescue
```

В `rescue A, B |e|:` типы разделяются запятыми. `ensure:` сохраняет ожидающий результат, если сама очистка не завершилась ошибкой. Для повторного выбрасывания пишите `raise e`; `raise` без аргумента не поддерживается. `throw` — управление потоком по метке; оно обходит `rescue`. У результатов есть `.ok?`, `.err?`, `.value`, `.error`; обращение к payload в неверном состоянии поднимает `ValueError`.

## 10. Параллельность и вывод

```sputnik
import task
from sync import Channel, Mutex, Atomic

local = task.async: 20 + 1           # кооперативная задача в том же strand
parallel = task.spawn: 21           # параллельная задача в новом strand
local.wait() + parallel.wait()      # 42; wait повторно поднимает ошибки дочерних задач

xs = [1, 2, 3, 4, 5, 6, 7, 8]
serial = xs.map: $it * $it           # последовательный проход по массиву
squares = xs.threaded(4, scatter: :chunks).map: $it * $it
# [1, 4, 9, 16, 25, 36, 49, 64]; 4 workers, по 2 соседних элемента в каждой части

counter = Atomic.new(0)
counter.update: $it + 1              # CAS может повториться: блок без побочных эффектов
mutex = Mutex.new()
mutex.synchronize: critical_work()   # разблокировка при раскрутке стека

print "Hello, #{name}"              # отображение, новая строка для каждого аргумента; null
p value                             # inspect; возвращает значение (Tuple для нескольких)
pp value                            # форматированный inspect; то же правило возврата
```

`.threaded(4, scatter: :chunks)` делит массив на непрерывные части с одной задачей на worker. `map` дожидается завершения и сохраняет исходный порядок; входные элементы и результаты должны быть разделяемыми. Для ускорения прохода по большим массивам с примерно одинаковой вычислительной работой на элемент выбирайте достаточно крупные части, чтобы окупить накладные расходы планирования. Режим по умолчанию `scatter: :atomic` динамически выдаёт следующий элемент и подходит для неравномерной работы.

Структурированные области дожидаются дочерних задач. Явная корневая область в спецификации — `async |task|:` (см. примечание о текущем бинарнике ниже). `task.async` может захватывать изменяемое состояние того же strand; `task.spawn` требует разделяемых захваченных значений, например глубоко замороженных данных. `task.sleep(seconds)` / `.yield()` кооперативно передают управление; у дескрипторов есть `.wait(timeout: seconds)`, `.cancel()`, `.resume()`. `Channel.new(capacity: 0)` — канал встречи отправителя и получателя; положительная ёмкость включает буфер. `.send(v)` / `.recv()` передают разделяемые значения. Закрывайте канал явно через `.close()`; опустошённый закрытый канал поднимает `ChannelClosedError`. `Mutex` не допускает повторного захвата той же задачей. `task.flow` добавляет `scatter_map(items, workers: 4) |item|: …` и `scatter_reduce`.

## 11. Модули

```sputnik
package app.users                    # первая форма после комментариев; необязательна для скриптов
import net.http as http              # обычный import net.http связывает имя http
from app.models import User as Person
import "../backend/models" as models
from "../backend/models.s" import Account

def display(user): user.name
export display, Person as User       # по умолчанию всё приватно; явный повторный экспорт
```

Импорты статические, располагаются на верхнем уровне перед обычными объявлениями и инструкциями. Импортированные имена — живые псевдонимы только для чтения. Принимаются исходники `.s`, `.spu` и `.sputnik`. Из корня репозитория: `build/sputnik program.s` запускает файл, `build/sputnik parse program.s` показывает синтаксический разбор.

`sputnik run backend/main.s` и `sputnik build backend/main.s -o build/app`
не требуют манифеста. Строковые пути `./` и `../` считаются от файла-импортёра;
интерполяция не допускается. Расширение можно опустить, `as` по умолчанию — имя
файла. Эквивалентные пути/symlink загружают один модуль один раз.
Именованные локальные импорты учитывают каталог импортёра и entry: точки
переходят в подкаталоги, префикс пакета entry можно снять. Установленные пакеты
не требуют `dependencies`. Необязательный ближайший `sputnik.build.json` / YAML
может содержать path overrides и форматы шаблонов, без списка файлов и повторения
точки входа. `sputnik pkg lock backend/main.s` фиксирует граф пакетов; локальные
исходники остаются изменяемыми.

`import my.orm as orm` подменяет путь `orm` на форк во всём графе: последующие `import orm`, `from orm import Model` и импорты зависимостей используют `my.orm`. Допустимо и `import my.orm as vendor.orm`; подмодули также перенаправляются. Повторный импорт того же binding разрешён, модуль инициализируется один раз. Работает в скриптах без манифеста и между ячейками ноутбука.

## 12. Необязательные профили и дополнения эталонной реализации

Эти возможности расширяют повседневное ядро; доступность зависит от выбранного тулчейна и хоста.

**Примечание о текущем бинарнике:** проверенный `build/sputnik` разбирает основные примеры, но отвергает заданные спецификацией оператор `??` и корневую форму `async |task|:`. Сейчас для значения по умолчанию только при null сохраните результат один раз и используйте `if value == null then fallback else value`; импортируемый API `task.async` / `task.spawn` задаёт текущую форму работы с задачами. Описание в спецификации не обещает полной поддержки всех профилей в рантайме.

| Профиль | Краткая форма |
| --- | --- |
| Числовой | Преамбула файла `numeric:` с отступами для `int: Int64` и `overflow: checked` (по умолчанию); опционально `wrapping`/`saturating`; явно `BigInt(value)`. [Числовой контракт](engineering/numeric-profile-v1.md) |
| Эффекты | `def pure(x as Int) -> Int !{}: x * 2`; эффекты вроде `!{net, async}`; вызываемый тип `Fn[Int -> Int !{}]` |
| Схема | `schema User:` с полями `id as Int`, `name as Str`, `email as Str?`; версия `schema Order v1:`; метаданные вроде `deprecated` / `@pii` |
| Контракты | `require condition`, `ensure condition`, `old(expr)`; `invariant condition` в классе; `property "name" \|xs as Array[Int]\|:` + `expect condition` |
| Рабочий процесс | `workflow ImportOrders:`; `step fetch !{net} retry: {max: 3}:`; `step commit !{db} idempotency_key: key:`; `compensate commit !{db}:` |
| Ускоритель | `gpu.map(xs) \|x\| -> F32 !{}: x * 2.0`; ограниченное подмножество чистых ядер |
| Наблюдение в ноутбуке | `h = Kernel.watch(x)` (также `@x`, `@@x`); `Kernel.revision(x)`; `Kernel.unwatch(h)` |
| Другие профили рантайма | Capabilities и sandbox, наблюдаемость и replay, DataFrame, компоненты Wasm, инструменты ИИ и происхождение данных, приватность / taint / lineage, Frozen: API и манифесты в части IV спецификации и документе о рантайме |

Текущий эталонный корпус также содержит полезные формы, ещё не полностью сведённые в основной спецификации:

```sputnik
inc = |x|: x + 1                     # отдельное лексическое замыкание
make_adder = |n|: |x|: x + n
def collect(*args, **kwargs): (args, kwargs)  # остаток: Tuple / Map именованных аргументов
[first, *middle, last] = [1, 2, 3, 4]       # остаток в середине последовательности
```
