No-GIL VM · native threads · compact syntax

Лаконичный язык для no-GIL runtime.

Amber берёт читаемость Python, пластичность Ruby, pattern matching и современный data-flow syntax — и ведёт их в VM без глобального lock: worker threads, strands, cooperative tasks, verified bytecode и full-native build pipeline живут в одной модели.

Block suffix, safe navigation и real strands — без синтаксического шума
SCROLL

Синтаксис без лишней позы

Сахар есть, но он компилируется в понятные формы.

Amber не пытается быть «ещё одним Python» или «ещё одним Ruby». Он собирает удачные идеи из разных миров и задаёт им строгую lowering-модель: удобно писать, не стыдно компилировать.

01
blocks

Block suffix вместо callback-лесов

Блок привязывается к вызову как отдельный channel, `_1/_2` работают только внутри implicit-block, а HIR видит уже явную closure. 

scores
  .select: _1 >= 80
  .map: _1 * 2
  .reduce 0: _1 + _2
02
matching

Pattern matching и multi-clause def

Деструктурирование, guards, pin-pattern и dispatch по клаузам — часть языка, а не протокол поверх `if`. 

def area(Point(x, y)): x * y
def area(Rect(w:, h:)): w * h
def area(_): 0
03
literals

Spread и условия в коллекциях

`*` и `**` — контекстный spread, conditional entries вычисляются слева направо и не притворяются магическими операторами. 

flags = [
  :base,
  :debug if debug?,
  *plugins,
]

opts = {**env, cache: true unless test?}
04
data flow

Safe navigation без `nil`-акробатики

`.?.` работает для методов, полей, индексов и callable-call; `if`, `unless`, `case` и циклы остаются выражениями. 

city = user
  .?.address
  .?.city
  .?.trim() or "unknown"
05
call ABI

Callable references без FFI-дыр

`&target` создаёт callable object, class object вызывается как constructor, а call/send/block-pass сходятся в единый VM ABI. 

normalize = &Text.normalize
make_user = &User

names.map(normalize)
admin = make_user(name: "Ada")

Меньше ритуала, больше смысла

Amber оставляет в коде действие, а не церемонию вокруг него.

Те же идеи, которые в других языках часто распухают в служебные конструкции, в Amber остаются рядом с доменной мыслью: поля, цепочки, matching, условные элементы и безопасный доступ.

Цепочка данных без callback-обвязки

Block suffix оставляет фильтрацию, проекцию и дедупликацию в одной читаемой линии потока.

Amber 4 строки

JavaScript 13 строк 
const seen = new Set();
const result = users
  .filter((user) => user.active && user.score >= 80)
  .map((user) => ({
    id: user.id,
    city: user?.profile?.city ?? "unknown"
  }))
  .filter((user) => {
    if (seen.has(user.id)) return false;
    seen.add(user.id);
    return true;
  });
matching

Варианты формы как клаузулы, а не лестница проверок

Multi-clause `def` показывает dispatch прямо в объявлении функции и не прячет его в условных ветках.

Amber 3 строки 
def area(Point(x, y)): x * y
def area(Rect(w:, h:)): w * h
def area(_): 0
TypeScript 10 строк 
function area(shape: Shape): number {
  if (shape.kind === "point") {
    return shape.x * shape.y;
  }
  if (shape.kind === "rect") {
    return shape.w * shape.h;
  }
  return 0;
}

Runtime без глобального замка

No-GIL VM: параллельность — часть модели исполнения.

Amber строит concurrency вокруг Worker → Strand → Task. `task.async` даёт кооперативные задачи внутри strand, `task.spawn` выносит работу в новый strand на worker thread, а verifier/root maps держат runtime безопасным для байткода и native backend.

⇄

Worker / Strand / Task

Несколько strands реально исполняются параллельно на worker threads; ordinary mutable state по умолчанию остаётся strand-confined.

↯

Кооперативная многозадачность

`wait`, `sleep`, `yield` и cancellation работают на safepoints; `task.sync:` временно запрещает same-strand переключение.

◇

Verifier, root maps, safepoints

`.amberbc` — data, not trusted code: loader проверяет структуру, dataflow, handler ranges и GC roots до исполнения.

✦

Full native build

Native profile сохраняет bytecode как source-of-truth, добавляет MIR/native metadata, root maps и безопасный fallback на VM.
